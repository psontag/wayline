# Route network spike: Upper Franconia

Question: do signed cycling routes from OSM give good multi-day trip proposals?

Generated by `pipeline/spike/propose.py`, except the verdict at the end. Data: Geofabrik `oberfranken-latest.osm.pbf`, Copernicus GLO-30 DEM.

## How it works

- Python 3.12. `pyosmium` reads the PBF (`extract.py`), `tifffile` reads the DEM, the rest is plain Python.
  Python because PBF parsing in Node needs more work and this is throwaway code.
- Graph: OSM nodes on route ways, compressed to edges between junctions, dead ends and nodes snapped to towns and stations.
- Edge score: network (icn 1.0, ncn 0.95, rcn 0.85, lcn 0.75, connector 0.4) x surface (paved 1.0, gravel/unknown 0.85, rough 0.6) x 0.7 on primary/secondary roads.
- Search: Dijkstra with cost = length / score². One-way: start -> via town -> end station. Loop: start -> A -> B -> start with A and B at 25-42 % of the length. Each leg penalizes edges of earlier legs (x5), each proposal penalizes its edges for later ones (x2), and a proposal may share at most 40 % with earlier ones.
- Stages: dynamic programming over towns with hotels within 2 km of the track, toward the target km per day. A hotel counts for its nearest town only.
- Ascent: sampled every 50 m from GLO-30, smoothed over 450 m. Only reported, not used in the search.
- `overview.png` shows all proposals. One color per stage.

Run:

```sh
python extract.py oberfranken-latest.osm.pbf extract.json
python propose.py extract.json <dem-dir> output
python plot.py extract.json output
```

## Verdict

Written by hand after looking at the numbers and `overview.png`.

Yes, with fixes. Signed routes give sensible multi-day trips. All 6 proposals run 99-100 % on signed routes and 76-92 % on icn/ncn/rcn. The weak parts are hotel data, ascent and the small region.

| Topic | Finding |
|---|---|
| Gaps | Good. 35 components; 71 short connectors (26 km in total) join 98.8 % of the network. Proposals use at most 1.4 km of connectors. |
| Route quality | Mostly sensible: they follow the Main, EV4, D11 and the Radrunde Oberfranken. Two problems: forced via towns cause short spurs (out and back on parallel roads, visible in B1, B2 and A3 in `overview.png`, not caught by the checks), and Upper Franconia is too small for 320 km one-way, so all A proposals are big arcs that end 40-100 km from Bamberg and fall 4-7 % short. |
| Paved data | Believable. 84-96 % paved, with surface tagged on 72-91 % of the km. Untagged cycleways and roads count as paved, which may be a little optimistic. |
| Hotels | Enough near the routes: 328 towns with at least one hotel. But 216 of them have only one, and many stops have 1-3 hotels. Counts are rough: a hotel goes to the nearest `place` node, so villages that are districts of Kulmbach or Bayreuth take hotels from the town. |
| Ascent | Copernicus GLO-30 was easy to use. Values look 20-50 % too high (e.g. 488 m for Bamberg - Kulmbach along the Main), because it is a surface model with trees and buildings. |
| Speed | Graph build and all searches run in about 4 s in Python. |

Next steps for the real pipeline:

- Build a larger region (all of Bavaria or Germany). One-way trips need room.
- Use junctions as via points, or drop a via when it creates a spur. Detect spurs, not only reused edges.
- Count hotels per municipality (admin boundary) and prefer stops with 3+ hotels.
- Take ascent from BRouter for the chosen proposals. Use DEM ascent in the graph only for rough filtering.
- Add scenery and nearby main roads to the score. This spike leaves them out.
- Route the station access instead of drawing a straight line.
